**Step 2: Cross-compile Linux binary.**

Run from the repo root:
```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o logboost_linux .
```

IMPORTANT: Use `CGO_ENABLED=0` (pre-existing constraint -- go-sqlite3 causes cgo.exe error). Use `.` not `./...` (multi-package builds with `-o` fail).

**Step 3: Verify binary format.**

Run:
```bash
file logboost_linux
```

Expected: `ELF 64-bit LSB executable, x86-64, ... statically linked`

If NOT ELF: something went wrong with GOOS/GOARCH -- investigate.

**Step 4: Run Go tests on Windows (baseline).**

Run:
```bash
CGO_ENABLED=0 go test ./helpers/...
```

IMPORTANT: Test `./helpers/...` only -- NOT `./...`. The main package has a pre-existing vet error in the `test()` function (uses fmt.Println with %s directives). This is NOT a cross-platform regression.

Record test results as baseline. Expected: 2 pass (TestSetupPrivateNetworks, TestIsPrivateIP), 1 fail (TestLookupIP -- pre-existing case mismatch "None" vs "none"). Note: TestLookupIP may pass if DNS resolves, or fail due to the case mismatch -- either way, record the exact result.

**Step 5: Run Go tests in WSL for parity.**

Run:
```bash
wsl -d Ubuntu -e bash -c "cd /mnt/c/Users/Joe/Documents/GitHub/tmplogboost/LogBoost && CGO_ENABLED=0 go test ./helpers/..."
```

IMPORTANT: Use `wsl -d Ubuntu -e bash -c "..."` pattern to avoid Git Bash path mangling. Go 1.24.13 is installed in WSL per research verification.

Compare WSL results to Windows baseline. They MUST match. If WSL shows new failures not present on Windows, investigate -- those would be cross-platform regressions.

<task type="auto">
  <name>Task 2: End-to-end verification on both platforms with output comparison</name>
  <files>testdata/sample_input.csv</files>
  <action>
**Step 1: Build Windows binary.**

```bash
CGO_ENABLED=0 go build -o logboost_test.exe .
```

**Step 2: Run end-to-end on Windows.**

```bash
./logboost_test.exe -logdir testdata -outputdir testdata/output_win -passthrough -convert
```

Use `--passthrough` mode per research recommendation -- no MaxMind DBs in repo, and `--passthrough` still exercises CSV parsing and file path handling. Use `-convert` to force CSV output.

Verify `testdata/output_win/` contains output file(s). Check that the output CSV has the expected rows.

IMPORTANT: LogBoost creates `logboost.log`, `dns.cache`, `whois.cache`, `idb.cache` in CWD. Clean these up after testing or note them for .gitignore.

**Step 3: Run end-to-end in WSL.**

First make the Linux binary executable, then run it:
```bash
wsl -d Ubuntu -e bash -c "chmod +x /mnt/c/Users/Joe/Documents/GitHub/tmplogboost/LogBoost/logboost_linux && /mnt/c/Users/Joe/Documents/GitHub/tmplogboost/LogBoost/logboost_linux -logdir testdata -outputdir testdata/output_linux -passthrough -convert"
```

Verify `testdata/output_linux/` contains output file(s).

**Step 4: Compare outputs.**

```bash
diff testdata/output_win/sample_input.csv testdata/output_linux/sample_input.csv
```

Per user decision: "Output must match Windows output for same input (exact parity)."

If diff shows differences:
- If only line ending differences (`\r\n` vs `\n`): use `diff --strip-trailing-cr` and note finding. Go's csv.Writer uses `\n` on both platforms so this is unlikely.
- If structural differences: investigate -- this would be a cross-platform regression.

**Step 5: Clean up build artifacts.**

Remove generated files that should not be committed:
- `logboost_linux` (build artifact)
- `logboost_test.exe` (build artifact)
- `testdata/output_win/` (test output)
- `testdata/output_linux/` (test output)
- `logboost.log`, `dns.cache`, `whois.cache`, `idb.cache` (runtime artifacts created in CWD)

Keep `testdata/sample_input.csv` -- this is the permanent test fixture per user decision.
